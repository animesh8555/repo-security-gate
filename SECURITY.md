# Security policy

This project contains review instructions, not a vulnerability scanner. A missed threat in a reviewed repository is not evidence that this workflow provides a security boundary.

If you find a vulnerability in this project, use the repository's Security tab and “Report a vulnerability” if private reporting is enabled. If it is unavailable, open an issue asking for a private reporting channel without disclosing exploit details. There is no published response-time commitment.

Do not post API keys, private files, personal data, or an active exploit against another project in a public issue. Report vulnerabilities in third-party repositories to their maintainers through their own security process.

If a credential was exposed, revoke or rotate it through the provider. Removing it from a file or adding it to .gitignore does not make the old credential safe.
